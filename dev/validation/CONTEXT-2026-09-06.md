## Isolated compaction and restart

Strictly decoded the settled session without claiming its lease or modifying its
files. Published the in-memory tree into a disposable workspace/session store.
The development-only compaction threshold was 50% (129,200 tokens), so the copied
220k-token estimate exercised automatic compaction without padding the history.
Normal settings and the original session remained unchanged. Live calls used
the already-connected account; tools were blocked from execution in the probe.

1. With the earlier summary prompt, two attempts reached the unchanged 60-second
   deadline. Instrumentation in the second attempt saw first summary text at
   8.536 seconds and 779 words/6,846 characters before cancellation. The ordinary
   request then completed using the original projection; no partial summary was
   committed. This exposed excessive summary generation rather than a silent
   transport wait in that measured attempt.
2. With the focused 500-word prompt, one automatic summary completed in 30.980
   seconds: 348 words, 3,252 characters, 700 reported output tokens. Estimated
   request input fell from 220,222 to 2,329 tokens. The following request reported
   1,681 input tokens and correctly recalled the latest app, entry point, runtime
   constraint, and final verification counts.
3. Closed the process and resumed the disposable session in a new Node process.
   The same anchor was restored; the next request completed without another
   compaction. It correctly recalled the latest project, verification counts,
   and remaining manual checks. Reported input was 1,874 tokens.
