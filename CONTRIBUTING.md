# Community and contributions

Jecode currently accepts public participation through Issues and Discussions.
Code changes are made through maintainer and invited-collaborator pull requests.

## Where to go

- Use [Discussions](https://github.com/giovannijecha/jecode/discussions) for
  questions, workflows, early ideas, and open-ended product conversation.
- Use [Issues](https://github.com/giovannijecha/jecode/issues) for reproducible
  bugs and focused feature requests that have a clear outcome.
- Use private vulnerability reporting from the repository Security tab for
  anything that could put users, credentials, or workspaces at risk.

Search existing conversations first. Keep reports concise, include the Jecode
version from **jecode --version**, and remove credentials, private source code,
workspace paths, and conversation transcripts before posting.

## Pull requests

Public pull requests are not accepted at this stage. Please open an Issue or
Discussion instead; a maintainer can validate the direction and carry the
change through the repository's own review workflow.

This boundary keeps product decisions and implementation ownership together
while the architecture and terminal interface are still settling before 1.0.

## A useful bug report

Include:

1. Jecode, Node.js, operating-system, and terminal versions.
2. Provider and model names, but never an API key.
3. The smallest sequence that reproduces the problem.
4. What happened and what you expected.
5. Sanitized output or a screenshot when it materially helps.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
